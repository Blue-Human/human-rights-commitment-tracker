# Repository instructions

Work directly on `main`, as requested by the repository owner. Do not create branches or pull requests unless the user explicitly asks for them. This preference supersedes the branch/PR workflow in older project context documents.

Preserve unrelated local changes. Run the checks appropriate to each change before pushing to `main`, and verify the production deployment when updating the public UI.

Follow the existing HRCT architecture and design. Preserve official recommendation text, assessment history, editorial review and the separation between public data and research drafts. Publish indicators and assignments when the user explicitly approves them, recording the approval, reviewer and date; do not request the same approval again. The owner explicitly approved the complete `spain-upr4-v1` catalogue, components, applicability decisions and assignments on 2026-10-04. Present these as accepted and published, without pending-review or unvalidated-proposal banners. Private draft edits and review metadata remain private. Never invent measurements, baselines or targets to populate charts; missing data is described as unavailable data, not missing editorial approval.
